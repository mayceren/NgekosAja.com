# Setup Internal Payment Simulator

Tidak memerlukan akun Midtrans, gateway, API key pembayaran atau layanan tambahan. **Aktivasi Cloud sudah disetujui dan selesai pada 20 November 2026**; lihat [hasil aktual](CLOUD_VERIFICATION.md). Jangan mengulang apply/deploy untuk aktivasi ini. Website tetap dijalankan dengan npm run dev atau Live Server pada http://127.0.0.1:5500 atau http://localhost:5500. Refresh halaman agar capability cache diperbarui.

Target aktual: project ngekosaja-development yang ditetapkan pengguna untuk development. CLI melaporkan main branch project ini sebagai environment=production; itu metadata branch Supabase, bukan nilai PAYMENT_ENVIRONMENT aplikasi. [Dokumentasi Supabase](https://supabase.com/docs/guides/deployment/branching/dashboard) menjelaskan label main/PRODUCTION pada setiap project. Sebelum aktivasi, persetujuan harus menyebut ref project yang sama, penggunaan khusus development dan akun fixture. Guard tidak mengizinkan PAYMENT_ENVIRONMENT=production atau ref project lain.

Langkah berikut merupakan referensi deployment/future review, bukan perintah untuk mengulang aktivasi yang sudah selesai:

1. Jalankan npm run payment:review secara read-only. Status setelah aktivasi: ngekosaja-development (wfmhsbdfdcugxblqsaob), 15 applied dan nol pending. Laporan terkini disimpan terpisah dari review sebelum apply. Untuk perubahan berikutnya, dry-run harus benar-benar lulus sebelum apply; manifest atau timeout bukan persetujuan ataupun bukti keberhasilan.
2. Tinjau migration, dua fungsi, guard, fingerprint dan laporan testing. Minta persetujuan untuk migration Cloud, deployment dua fungsi, konfigurasi server dan fixture testing. Jangan reset, include-all, menjalankan seed massal atau mengulang provisioning akun.
3. Setelah disetujui, terapkan hanya migration pending yang sudah ditinjau. Jalankan supabase/review/phase5-postflight.sql secara read-only dan cocokkan katalog/RLS/grants/publication. Simulator masih OFF secara default.
4. Setelah persetujuan konfigurasi, isi Supabase Edge Function Secrets melalui Dashboard: PAYMENT_SIMULATOR_ENABLED=true, PAYMENT_ENVIRONMENT=development, PAYMENT_ALLOWED_PROJECT_REF=wfmhsbdfdcugxblqsaob, PAYMENT_ALLOWED_ORIGINS berisi origin HTTP(S) website yang tepat, dipisahkan koma. Supabase menyediakan SUPABASE_URL/ANON_KEY/SERVICE_ROLE_KEY di server; jangan salin privileged key ke frontend/chat/repository.
5. Aktifkan switch DB hanya di project development yang sama melalui SQL administratif yang disetujui: UPDATE private.payment_simulator_settings SET enabled=true WHERE singleton AND environment='development' AND project_ref='wfmhsbdfdcugxblqsaob';. Tidak ada UI atau RPC browser untuk mengubah switch ini.
6. Deploy hanya simulate-rent-payment dan simulate-boost-payment dengan verify_jwt=true. CLI 3.2.0: supabase functions deploy simulate-rent-payment simulate-boost-payment --remote=wfmhsbdfdcugxblqsaob --use-api. Jangan gunakan --no-verify-jwt atau --prune. Deployment pertama sudah dijalankan; deploy ulang hanya untuk perubahan yang ditinjau/disetujui berikutnya.
7. Gunakan akun development existing dan password melalui login biasa. Jangan buat ulang akun atau ubah role/password. Akun pribadi, prospect dan administrator tidak mendapat akses settlement. Owner membuat invoice test yang disetujui untuk Tenant A/B; untuk Boost, publikasi properti fixture dan campaign yang akan dibuat juga harus disetujui.
8. Refresh website, buka tagihan/Boost → checkout → metode ilustratif → Konfirmasi Pembayaran. Periksa invoice paid, satu transaksi is_simulation=true, notifikasi, receipt, campaign 30 hari, reload, isolasi antar-akun/perangkat dan Realtime. Jangan mengklaim E2E Cloud sebelum langkah tersebut benar-benar diuji.

Template non-secret: supabase/functions/.env.example, disabled default. Jika memakai file lokal, gunakan .env.local yang diabaikan Git; masukkan informasi privat lewat editor/terminal pribadi, bukan argumen shell atau chat. Tidak perlu mengubah config/runtime.js. Untuk menonaktifkan, ubah PAYMENT_SIMULATOR_ENABLED=false dan/atau switch DB enabled=false; riwayat tetap dapat dibaca.

Tidak mendukung Production atau pembayaran sungguhan. Pengujian otomatis lokal memakai database scratch, HTTP mock dan fixture yang eksplisit; test tidak mengirim email atau membuat akun Cloud.
